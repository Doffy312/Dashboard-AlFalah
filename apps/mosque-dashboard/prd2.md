Product Requirement Document (PRD)Nama Proyek: Dashboard Takmir Masjid Al-Falah Berbasis WebVersi: 1.0Target Rilis: Q3 - 2026Status: Draft Proproposal1. Latar Belakang & Tujuan (Background & Objective)Manajemen masjid Al-Falah saat ini masih menghadapi tantangan dalam hal transparansi, efisiensi administrasi, pencatatan keuangan, dan evaluasi program kerja. Pembuatan aplikasi berbasis web ini bertujuan untuk menyentralisasi seluruh data masjid, memudahkan kolaborasi antar takmir (Ketua, Sekretaris, Bendahara), serta menyediakan fitur analitik untuk mendukung pengambilan keputusan yang lebih tepat sasaran di masa mendatang.2. Pengguna & Hak Akses (User Personas & Roles)Aplikasi ini menggunakan metode Role-Based Access Control (RBAC) dengan detail sebagai berikut:Peran (Role)DeskripsiHak Akses UtamaKetua TakmirPengawas tertinggi dan pengambil keputusan masjid.Read-only semua modul, menyetujui anggaran program, melihat seluruh grafik analisis keuangan.SekretarisPenanggung jawab administrasi dan operasional kegiatan.Full-access (CRUD) untuk modul Program Kerja dan Database Jemaah.BendaharaPenanggung jawab sirkulasi keuangan dan aset masjid.Full-access (CRUD) untuk modul Arus Kas, Inventaris, dan Budgeting Program Kerja.3. Spesifikasi Fitur Utama (Functional Requirements)3.1. Modul Dashboard UtamaFR-01: Sistem harus menampilkan ringkasan informasi terkini (Saldo kas, total jemaah, jumlah aset, program kerja terdekat) dalam bentuk widget card.FR-02: Sistem harus menampilkan kalender kegiatan interaktif yang berisi jadwal program kerja bulan berjalan.3.2. Modul Manajemen Program KerjaFR-03: Sekretaris dapat membuat, membaca, memperbarui, dan menghapus (CRUD) data Program Kerja.FR-04: Setiap program kerja harus memiliki atribut: Nama Program, Tanggal Pelaksanaan, Penanggung Jawab, Estimasi Anggaran, Status (Direncanakan/Berjalan/Selesai/Dibatalkan).FR-05: Sekretaris dapat menginput teks evaluasi (catatan kendala, jumlah kehadiran jemaah) setelah status program diubah menjadi "Selesai".3.3. Modul Database JemaahFR-06: Sekretaris dapat melakukan CRUD data jemaah.FR-07: Setiap data jemaah wajib memiliki atribut: Nama, Alamat, No. HP/WhatsApp, Kategori (Muzakki/Mustahik/Yatim/Lansia/Umum).FR-08: Sistem harus memiliki fitur pencarian (search) dan filter berdasarkan kategori jemaah untuk memudahkan distribusi bantuan/zakat.3.4. Modul Arus KasFR-09: Bendahara dapat mencatat transaksi pemasukan dan pengeluaran.FR-10: Setiap transaksi wajib memiliki: Tanggal, Nominal, Kategori (Infaq/Operasional/Sosial, dll), Deskripsi, dan Upload Bukti Transaksi (Gambar/PDF).FR-11: Bendahara dapat menghubungkan transaksi pengeluaran tertentu dengan Program Kerja yang relevan.3.5. Modul Inventaris MasjidFR-12: Bendahara dapat melakukan CRUD data aset masjid.FR-13: Setiap aset memiliki atribut: Nama Barang, Jumlah, Tanggal Perolehan, Lokasi Penyimpanan, Kondisi (Baik/Rusak Ringan/Rusak Berat).3.6. Modul Analisis Keuangan & KegiatanFR-14: Sistem harus secara otomatis mengkalkulasi dan menampilkan grafik perbandingan antara Anggaran Rencana vs Realisasi Pengeluaran per program kerja.FR-15: Sistem harus menampilkan tren infaq/pemasukan bulanan dalam bentuk line chart untuk melihat pola fluktuasi keuangan.FR-16: Sistem mampu mengeksport laporan keuangan (Arus Kas) ke dalam format PDF atau Excel.4. Kebutuhan Non-Fungsional (Non-Functional Requirements)Keamanan (Security): Seluruh password pengguna wajib di-enkripsi (misal memakai bcrypt). Sesi login dibatasi (session timeout) setelah 30 menit tidak ada aktivitas.Performa (Performance): Halaman dashboard dan grafik analitik harus dapat dimuat (load time) dalam waktu kurang dari 2 detik pada koneksi internet standar.Responsivitas (UI/UX): Tampilan web harus mobile-friendly (responsif) agar takmir dapat menginput data dengan mudah melalui smartphone mereka.Ketersediaan Data (Availability): Sistem harus memiliki mekanisme auto-backup database berkala (misal seminggu sekali) untuk mencegah kehilangan data keuangan masjid.5. Metrik Keberhasilan (Success Metrics)Adopsi Pengguna: 100% pengurus takmir inti (Ketua, Sekretaris, Bendahara) aktif menggunakan aplikasi ini untuk operasional bulanan dalam waktu 2 bulan setelah rilis.Akurasi Data: Selisih antara pencatatan kas di sistem dengan uang fisik di lapangan adalah 0% (tidak ada human error dalam kalkulasi otomatis).
